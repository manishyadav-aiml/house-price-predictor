🏠 House Price Predictor
California Housing | Linear Regression | Machine Learning









[!\[Security Policy\]\(https://img.shields.io/badge/Security-Policy-blue.svg)](SECURITY.md)

A complete, beginner-friendly machine-learning project that explores the California Housing dataset, trains Linear Regression and Ridge Regression models, evaluates their performance, generates a PDF report, and provides predictions through a Flask-based web application.

⚙️ Installation and Setup
Prerequisites
- Python 3.11 or 3.12
- Git
- pip
- Internet connection for downloading the dataset
1. Clone the repository
git clone https://github.com/manishyadav-aiml/house-price-predictor.git
2. Navigate to the project directory
cd house-price-predictor
3. Create and activate a virtual environment
Windows PowerShell:
python -m venv .venv
.venv\Scripts\Activate.ps1
If PowerShell blocks activation, you can use the virtual environment's Python directly:
.venv\Scripts\python.exe -m pip install -r requirements.txt
Linux / macOS:
python3 -m venv .venv
source .venv/bin/activate
4. Install dependencies
python -m pip install -r requirements.txt
5. Configure environment variables
python setup_env.py
This creates a local .env file containing application configuration and a generated secret key. Do not commit .env to Git.
6. Train the machine-learning models
python train.py
The training script downloads and processes the California Housing dataset, trains the models, evaluates performance, and saves the trained model files.
7. Run the application
python app.py
Open the application in your browser:
http://127.0.0.1:5000
Demo-model note: If the dataset cannot be downloaded, the application can fall back to a synthetic demo model and display a demo warning. Run python train.py with internet access to train using the real California Housing dataset.

🧠 Machine Learning Workflow
Dataset
The project uses the California Housing dataset.
- 20,640 observations.
- 8 input features.
- Target variable: MedHouseVal.
- Housing data based on the 1990 California census.
Input Features
Feature	Description
MedInc	Median income
HouseAge	Median house age
AveRooms	Average number of rooms
AveBedrms	Average number of bedrooms
Population	Block population
AveOccup	Average household occupancy
Latitude	Geographic latitude
Longitude	Geographic longitude


Baseline Model
The baseline model uses:
- StandardScaler
- LinearRegression
- Scikit-learn Pipeline
- 80/20 train-test split
- Fixed random state of 42
Improved Model
The improved model uses:
- RidgeCV
- Feature engineering
- Ratio-based features
- Log transformations
- Geographic distance features for major California cities
Evaluation Metrics
The models are evaluated using:
- Mean Absolute Error (MAE): average absolute prediction error.
- Root Mean Squared Error (RMSE): square root of the average squared prediction error.
- R² Score: proportion of target variance explained by the model.

🔌 API Reference
The application provides REST API endpoints for authentication, predictions, feedback, and user history.

All write operations require the X-CSRF-Token header. Obtain the token through GET /api/session.
Method	Endpoint	Description
GET	/api/session	Get current user and CSRF token
GET	/api/meta	Get feature ranges, model metrics, and demo status
POST	/api/predict	Generate a house price prediction
POST	/api/predict-batch	Generate predictions from a CSV upload
POST	/api/register	Register a user
POST	/api/login	Authenticate a user
POST	/api/logout	Log out a user
GET	/api/history	Retrieve prediction history
DELETE	/api/history	Delete prediction history
POST	/api/feedback	Submit feedback
GET	/api/admin/stats	Retrieve administrator statistics


Example prediction request
{
  "MedInc": 5,
  "HouseAge": 20,
  "AveRooms": 6,
  "AveBedrms": 1,
  "Population": 1000,
  "AveOccup": 3,
  "Latitude": 37.8,
  "Longitude": -122.3,
  "model": "improved"
}
The request must include the required CSRF header. The response schema is defined by the running application.

🚀 Deployment
The application is deployed on Vercel.

Production URL:
https://house-price-predictor-blond.vercel.app/

Deployment platform: Vercel

The deployed application uses environment variables for configuration. The current deployment configuration includes:
- APP_ENV
- DATABASE_PATH
- SECRET_KEY
Configure secrets through the hosting provider's environment-variable settings. Never commit production secrets to the repository.
Deployment and persistence limitation
The current Vercel configuration uses /tmp/app.db for SQLite storage. Files stored in Vercel's temporary filesystem are not guaranteed to persist between executions or deployments.

Therefore, user accounts and prediction history should not be considered permanently stored in the current deployment. For persistent production storage, connect the application to a managed database.
Local production-style command
For a compatible server environment, the project README's original deployment command is:
APP_ENV=production gunicorn -w 2 -b 0.0.0.0:8000 app:app
Set SECRET_KEY and ALLOWED_ORIGINS appropriately for the hosting environment, and serve production traffic over HTTPS.
The Docker setup is included in the repository but has not been verified as tested. Do not assume the Docker deployment path is production-ready without testing it.

⚠️ Limitations
- The dataset is based on 1990 California census information.
- Predictions represent census block-group averages, not individual property valuations.
- The target price is capped at $500,000 in the original dataset.
- Model performance depends on the quality and limitations of the training dataset.
- The application is intended for educational and demonstration purposes, not actual real-estate valuation.
- Vercel temporary SQLite storage does not guarantee persistent user data.
- If the dataset cannot be downloaded, the application can fall back to a synthetic demo model. The application displays a demo warning in that situation.
For real-dataset training, run:
python train.py
with an internet connection.
